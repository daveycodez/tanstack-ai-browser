# Structured output

Shared browser-local constrained decoding for the WebGL and Transformers.js TanStack adapters. Native adapters keep their runtime's public guided-generation APIs. No upstream runtime patches are required.

`createConstraint({ schema, tokenizer, eosTokenId?, maxTokens? })` creates a generation-local matcher. `computeMask()` returns a Uint32 bitset with token `id` in bit `id & 31` of word `id >>> 5`; filter logits before candidate selection and sampling. `accept(id)` commits an emitted token. `clone()` creates independent state for speculative prefixes. Dispose matchers after every success, failure, or cancellation.

`complete` means the current bytes are an accepted schema-valid value. An accepting numeric prefix such as `1` may still legally extend to `12`; consumers must use the returned mask rather than forcing EOS solely from `complete`. For root schemas proven to exclude numbers, the wrapper permits EOS only once a complete value is reached, preventing trailing prose and unbounded whitespace. Unknown or potentially numeric root schemas retain valid continuations.

The backend is pinned to `llguidance@0.2.1`'s lean JSON Schema entry. It is loaded lazily on the first constrained generation. Tokenizer byte conversion is cached by tokenizer identity. Pass the exact HF tokenizer or a bridge containing `tokenizerJSON`, `eos_token_id`, and special-token metadata; independently decoding token strings is not a valid byte conversion. Explicit raw token byte arrays are also supported by the backend.

The practical schema profile includes objects, arrays, strings, numeric bounds, const/enum, composition, conditionals, and local references. It is not complete JSON Schema conformance. Unsupported assertion keywords (including unevaluatedProperties/unevaluatedItems, dynamic references, and external references) fail explicitly. Unknown format names are annotations, not enforced assertions. URI/email/IDN coverage has the upstream profile's documented limitations. See [the pinned backend profile](https://github.com/nico-martin/llguidance-js/blob/main/docs/JSON_SCHEMA_PROFILE.md).

The backend's prefix pruning can be conservative for complex assertions: an allowed prefix may lead to a later dead end. Final acceptance is exact for the supported profile. Dead ends and invalid tokenizers are explicit errors; there is no prompt-only downgrade. The wrapper introduces no default output-token or output-byte cap. Generation limits remain owned by the caller/runtime; parser depth/resource safety limits can still reject pathological schemas.

Native conformance tests in this package bundle adapter source with fake public runtime boundaries. They verify exact schema forwarding, preserved tool argument assertions, cancellation forwarding, unsupported-schema errors without lossy fallback, and truncation errors for wllama/apfel. They are contract tests, not proof that a native browser/model is available or that every backend supports every schema feature.

Run checks with `pnpm nx run-many -t test,typecheck,lint,build -p structured-output --skipSync`.

Prompt API's current public interface exposes neither a per-response output-token cap nor a thinking-token budget. Its context-window metadata is not an equivalent output limit. Its adapter therefore does not advertise those unsupported options; native schema enforcement is still available through `responseConstraint`. Wllama and apfel accept `maxTokens` at adapter level and map it to native `max_tokens` (legacy native fields remain supported, with canonical `maxTokens` taking precedence).

Cancelling a wllama chat while its model loads cancels that caller's wait and prevents its inference request. The shared model download can continue populating the browser cache; explicit model unloading/model switching still owns cancellation of that background load.

Constrained JSON uses compact punctuation: the compiler receives root `x-guidance` hints with `whitespace_flexible: false`, `key_separator: ":"`, and `item_separator: ","`. These formatting hints prevent unbounded whitespace between object/array tokens. They override caller formatting hints only; the caller's schema object is copied, all instance assertions remain intact, and whitespace inside JSON string values is preserved. Boolean schemas are wrapped in an equivalent `allOf` root to carry the formatting hints.

Guided tool routing constrains the schema actually supplied by the caller. For a closed parameter object, use `additionalProperties: false` (for Zod, `z.strictObject(...)`). An open JSON Schema permits extra fields by design; masking does not silently narrow it or make tool-selection decisions deterministic. Required choices use constrained selection and arguments; named choices skip selection. Automatic choice keeps native model routing and validates parsed arguments, adding a constrained argument generation only when the draft is invalid. Usage is aggregated; thinking/output budgets apply per model generation.

`validateStructuredValue(schema, value)` validates parsed native tool arguments locally using a fixed byte vocabulary, without a model tokenizer or inference call. It returns `false` for ordinary invalid values and throws for unsupported schemas. Non-JSON values such as non-finite numbers, undefined members, sparse arrays, class instances, bigint, functions, and cycles are rejected before serialization so JSON.stringify cannot silently weaken validation by coercing or omitting them. This supports hybrid tool calling: preserve the model's native routing, retain already-valid arguments, and use constrained generation only to repair invalid arguments.
