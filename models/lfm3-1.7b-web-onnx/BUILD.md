# Building LFM3-1.7B-Web-ONNX

Two models live in the repo:

- `onnx/model_q4f16.onnx`: the WebGPU build. Made from [`q4f16/`](q4f16) on Oct 28–29, 2026.
- `onnx/model_q4.onnx`: the same weights with float32 activations, for onnxruntime-web on the CPU (WebAssembly). Made from [`q4/`](q4) on Oct 30, 2026.

The source is [onnx-community/LFM3-1.7B-ONNX](https://huggingface.co/onnx-community/LFM3-1.7B-ONNX) at commit `ab9fec4c681a25bec3b48b0b97a62fc2660a2985`. See the [model card](README.md) for what each step changes and why.

## q4f16

Run everything from `q4f16/` (see [the setup](../README.md#setup) for the venv).

### 1. Downloads

```bash
hf download onnx-community/LFM3-1.7B-ONNX --revision ab9fec4c681a25bec3b48b0b97a62fc2660a2985 --local-dir dl \
  --include "onnx/model_fp16.onnx*" "onnx/model_q4f16.onnx*" "*.json" "chat_template.jinja"
hf download Salesforce/wikitext --repo-type dataset --local-dir dl/wikitext \
  --include "wikitext-2-raw-v1/train-*" "wikitext-2-raw-v1/test-*"
```

The scripts run models on onnxruntime's CPU, which has only a float32 `CausalConvWithState` kernel. `cpu_patch.py` writes a copy of a graph that runs there. The copy shares the original's weights file.

```bash
venv/bin/python -I scripts/cpu_patch.py dl/onnx/model_fp16.onnx dl/onnx/model_fp16.cpu.onnx
venv/bin/python -I scripts/cpu_patch.py dl/onnx/model_q4f16.onnx dl/onnx/model_q4f16.cpu.onnx
```

### 2. Calibration data and GPTQ statistics

`make_calib.py` writes about 36k tokens: chunks of WikiText-2 *train* plus chat replies generated by the fp16 model. `collect_h.py` runs the fp16 model on them and saves, for every weight matrix, the input statistics (H = XᵀX) that GPTQ needs.

```bash
venv/bin/python -I scripts/make_calib.py dl dl/wikitext/wikitext-2-raw-v1/train-00000-of-00001.parquet dl/onnx/model_fp16.cpu.onnx out/calib.json
venv/bin/python -I scripts/collect_h.py dl/onnx/model_fp16.cpu.onnx out/calib.json out/H
```

### 3. Vocabulary (128k → 49,152 rows)

`vocab_trim.py` picks the tokens to keep and writes a consistent tokenizer, configs and `keep_ids.json`. It checks itself against test chats. Those chats were generated by an intermediate full-vocabulary GPTQ build (block size 128), so make that first:

```bash
venv/bin/python -I scripts/build.py --src dl/onnx/model_q4f16.onnx --fp16 dl/onnx/model_fp16.onnx --rope 16384 --gptq out/H --bs 128 --out out/gptq128
mkdir -p out/gptq128_nodup && mv out/gptq128/model_q4f16.onnx_data out/gptq128_nodup/
venv/bin/python -I scripts/nodedup.py out/gptq128/model_q4f16.onnx out/gptq128_nodup/model_q4f16.onnx
venv/bin/python -I scripts/cpu_patch.py out/gptq128_nodup/model_q4f16.onnx out/gptq128_nodup/model_q4f16.cpu.onnx
venv/bin/python -I scripts/gen_test_chats.py dl out/gptq128_nodup/model_q4f16.cpu.onnx out/test_chats.json

venv/bin/python -I scripts/vocab_trim.py dl out/calib.json out/test_chats.json 49152 out/vocab49152
```

Leave `MINCOUNT` unset. It was only for experiments.

### 4. Weights

This is the `f32_v48k` build in [`build_targets.sh`](q4f16/scripts/build_targets.sh):

```bash
# GPTQ 4-bit, block 32; gate/up/q/k/v symmetric so the fused WebGPU kernels apply; rotary caches cut to 16k
venv/bin/python -I scripts/build.py --src dl/onnx/model_q4f16.onnx --fp16 dl/onnx/model_fp16.onnx --rope 16384 \
  --gptq out/H --bs 32 --keep-fused --fused-sym32 --out out/g32tmp
# the LM head reads the embedding directly (no Reshape, so no second copy at load)
mkdir -p out/g32tmp_nd && mv out/g32tmp/model_q4f16.onnx_data out/g32tmp_nd/
venv/bin/python -I scripts/nodedup.py out/g32tmp/model_q4f16.onnx out/g32tmp_nd/model_q4f16.onnx
# keep only the 49,152 vocabulary rows
venv/bin/python -I scripts/vocab_model.py out/g32tmp_nd/model_q4f16.onnx out/vocab49152/keep_ids.json out/f32_v48k
```

### 5. Flash attention for the sliding-window layers

This edits the graph only, so the weights file is copied unchanged:

```bash
mkdir -p final/onnx
venv/bin/python -I scripts/sliding_window_bias.py out/f32_v48k/model_q4f16.onnx final/onnx/model_q4f16.onnx
cp out/f32_v48k/model_q4f16.onnx_data final/onnx/
cp out/vocab49152/{tokenizer.json,tokenizer_config.json,special_tokens_map.json,chat_template.jinja,config.json,generation_config.json} final/
```

`sliding_window_unit.py` checks the bias against `local_window_size` on a single attention op. `sliding_window_cmp_cpu.py` compares the whole model before and after.

### Checking a build

These produce the card's numbers. Each takes `label=path` pairs, so several builds compare in one run:

- `eval_xvocab.py`: WikiText-2 perplexity per original token, plus top-1 agreement and KL divergence from fp16 on chat prompts. It works across vocabularies.
- `tool_rate.py` and `toolcall_check.py`: whether the model starts its reply with a tool call on 20 prompts that need one.
- `wikippl.py`, `evaluate.py`, `think_rate.py`: older checks, run against full-vocabulary builds.
- `measure_all.sh` with `nodetest/`: GPU memory, prompt speed, and WebGPU compared with the CPU (onnxruntime-node, `webgpu` package).

Example (run `cpu_patch.py` on the build first):

```bash
V=out/vocab49152
SKIPKEEP=$V/keep_ids.json venv/bin/python -I scripts/eval_xvocab.py "$PWD" out/eval.json \
  fp16=dl/onnx/model_fp16.cpu.onnx@dl orig=dl/onnx/model_q4f16.cpu.onnx@dl \
  web=out/f32_v48k/model_q4f16.cpu.onnx@$V@$V/keep_ids.json
```

### Experiments

These scripts are kept for the record. None of them feed the published build:

- `build_all.sh`, `build_ablate.sh`, `build_roles.sh`, `build_gptq.sh`: other block sizes, GPTQ compared with plain rounding, and which projections are sensitive.
- `build_bs32.sh`: the 80k-vocabulary build.
- `build_qexp.sh`, `build_q.py`, `sens.sh`: 2-bit layers.
- `build_targets.sh` (apart from `f32_v48k`): the 550 to 750 MB builds.

## q4

`q4/scripts/convert.py` turns the published q4f16 graph into float32 activations. The 4-bit weights are copied byte for byte. Float16 scales and constants are widened exactly to float32. Two other changes:

- The sliding-window layers go back to `local_window_size`, as in onnx-community's q4. The flash-attention change only matters on WebGPU.
- The `GatherBlockQuantized` embedding lookup is rebuilt from standard ops, because the WebGPU-enabled WebAssembly builds of onnxruntime-web 1.31.1 have no CPU kernel for it.

Run from `q4/`. The source was the published repo at `3c75909fbf17af6f734263e9cee75625bcfd7523`, when it was still named `daveycodez/LFM3-1.7B-Web`:

```bash
hf download daveycodez/LFM3-1.7B-Web-ONNX --revision 3c75909fbf17af6f734263e9cee75625bcfd7523 --local-dir downloads/web
venv/bin/python -I scripts/convert.py downloads/web/onnx/model_q4f16.onnx out/window --sliding window
```

This writes `out/window/model_q4.onnx` and `model_q4.onnx_data`. `check_embed.py` compares the rebuilt embedding lookup with the original for every token id. `verify_structure.py` checks the graph against the q4f16 one. `node/test.mjs` runs it on onnxruntime-web's WebAssembly builds, and `tjs/e2e.mjs` runs it through Transformers.js.
