# Prompt compaction: v18 → v19

Latest accepted run: 2026-11-04, Chrome on Mac. The compact machine-readable
results are in [latest.json](latest.json). Raw reports and rejected experimental
wordings stay outside the repository.

## What changed

Only serialization changes: shorter policy/rules, conditional explanations, glossary
definitions folded into factual headings, and concise card wording. The full board,
last five turns, every legal action and its descriptive response label/order remain.
Duplicate board piece counts are omitted; the piece lists and AI material balance remain.
Net points, zeroes, both players in witness lines, Human reply/capture/promotion counts,
repetition, promotion distances, and king safety/activity meanings are retained.

The candidate explicitly scopes Human replies to *after each possible AI action*.
It preserves every Human reply/best AI response and forced captures until a turn has
no capture or the game ends. Extra checked Human/AI pairs are explained when used.

No outcome/search, case expectations, schema, sampling, generation limits, adapters,
or engine changes. There is one shared prompt for all models. No recommended move,
ranking, automatic fallback, or retry is added. Version 18 remains selectable.

## Quality

All 44 existing positions, two seeded action orders per position, thinking off,
model-default sampling. The 32 scored positions produce 64 scored trials per version.
The other positions are diagnostics, including one forced turn which skips inference.
Half the cases run v18 then v19; the other half run v19 then v18. Input ordering and
accepted moves match exactly. The six historical holdouts are compatibility checks,
not new unseen tests.

| Model | v18 passes | v19 passes | Mean full input, v18 → v19 |
|---|---:|---:|---:|
| LFM3-1.7B-GGUF | 59/64 | 59/64 | 1,257.6 → 881.0 |
| Gemini Nano | 59/64 | 59/64 | 1,232.8 → 871.7 |
| Qwen3.5-2B-GGUF | 52/64 | 57/64 | 1,238.7 → 875.9 |

All 516 inferred decisions and 12 forced turns were legal, with zero generation
errors. These are observed suite results, not proof that model behavior is identical
or that Qwen's long-game strength improved. Earlier candidate wordings were rejected
for tactical regressions.

All 528 recorded quality inputs were regenerated byte for byte after cleanup/default
activation; all 264 version pairs had identical legal action order and scoring.
Regression tests additionally check both player colors and reversed move orders.

## Serial production replay

The existing replay selects the first seven non-forced AI decisions from a recorded
real game. Same positions, session, production action ordering and ordinary cache
settings in both versions. LFM3 runs alone: warm both complete sequences, then record
v18/v19/v19/v18. Each block has an excluded first-position primer. In total, 18 warm-up
calls are excluded and 56 calls are recorded.

| Measure | v18 | v19 |
|---|---:|---:|
| Mean full input | 1,498.3 tokens | 1,025.1 tokens |
| Changed-turn median, 12 samples/version | 646.5 ms | 525.8 ms |
| Changed-turn prompt processing median | 418.1 ms | 289.6 ms |
| Exact-retry median, 14 samples/version | 217.7 ms | 217.2 ms |

That is **31.6% fewer input tokens** (473.1 saved per decision on average) and
**18.7% lower changed-turn median latency**. Exact retries are effectively unchanged.
Counts include the adapter's schema guidance and chat framing, using native usage.

Savings vary: the replay's individual positions range from 29.8% to 32.6%; the wider
suite includes smaller endgames and averages about 29–30% across tokenizers. This is
an average reduction, not a guaranteed minimum for every turn. Quality-run timings
were concurrent and are excluded from speed claims. The replay is warm, not a cold
model-load, mobile, whole-game, or engine-throughput benchmark.

## Reproduction

[The browser protocol](prompt-comparison.ts) exports `comparePromptQuality` and
`comparePromptTiming`. Invoke from an explicitly started browser benchmark page,
with separate WebGL documents per model and Prompt API in the top-level page. Run
serial timing only after quality runtimes have stopped. Persist each emitted event.
Use the normal `/bench` controls for individual v18/v19 case checks.

CPU counts with the production tokenizer, without inference:

```sh
node --experimental-strip-types apps/checkers/bench/measure-concise-prompt.mjs \
  /path/to/tokenizer.json /path/to/chat_template.jinja /tmp/checkers-prompt-counts.json
```

This uses fixture legal order; native usage in the matched browser trials is
authoritative. The reconstructed full input matched a captured LFM3 request exactly
(1,730 tokens). Source hashes and current run settings are in `latest.json`.
